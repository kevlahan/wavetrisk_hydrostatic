# Stage234: resident primitive producers, velocity gradients and direct retention

## Scope

Stage234 moves the regular, southwest and pentagon primitive calculations, and
final velocity gradients, onto final block owners for RK interstages. Pressure
feeds these consumers through actual owner results. The resulting velocity
values populate retained block tendency storage directly, without a
geometry-owner-to-block capture. The explicit return needed by the current RK
consumer remains.

**The full tendency migration is still incomplete.** Diffusion prepasses,
scalar flux/physics callbacks, mass restriction/divergence, velocity-source
execution, initial-stage lifetimes and reference aliases still depend on the
geometry-owner path. Domain numerical arrays cannot yet be deleted. No speedup
or MPI scaling improvement is claimed, and no cluster kit is supplied.

The build remains opt-in: `BLOCK_PRIMITIVES=on` requires `BLOCK_COLUMNS=on` or
`check`, and `STAGE203=on`. `BLOCK_PRIMITIVES=check` adds independent, bitwise
comparisons with the original regular/SW/pentagon and gradient arithmetic.
The normal build defaults to both features off. The qualified regime is the
compressible climate fixture and its tested physics configuration.

## Producer and consumer connections

- `parallel_block_primitive_walk_mod` enumerates the original regular/SW visits
  using topology only. `comp_offs3` is shared with the compatibility traversal.
  The consumer checks the actual operation order and stencil identities.
- `parallel_block_resident_operands_mod` requests exact stencil operands. Interior
  mass, temperature, means and velocity come from final-owner `Block_Data`.
  Explicit aliases come from the completed provisional inverse; alias reference
  means still come from geometry owners. Requests are deduplicated by physical
  storage identity, including the alias identity, rather than coordinates.
- Regular and SW kernels execute together on the pressure-column owner. The SW
  kernel consumes the regular kernel's PV context. Pressure visit numbers follow
  the pressure writes preceding each primitive operation, not the distinct
  primitive traversal's visit count.
- Some extra boundary primitive visits have no preceding pressure producer.
  Their unused Bernoulli writes are omitted. A per-layer definition map guards
  every retained Bernoulli restriction and active gradient input: reading one
  of those omitted values aborts. PV, vorticity and kinetic-energy results at
  those visits still execute and are independently checked.
- Pentagon corrections receive the exact preceding regular/SW vorticity result
  slots, plus resident density and velocity. This is currently a result relay
  through the geometry owner, not a Domain-vorticity read. A dependency on an
  earlier pentagon correction is explicitly rejected until represented as an
  additional ordered phase; it is not silently approximated.
- Bernoulli/Exner restrictions propagate integer producer addresses alongside
  the remaining compatibility restriction. The final gradient requests those
  actual owner-produced values and resident density operands. Its velocity
  source remains an explicit input from the unmigrated source program.
- The final gradient retains its active-node results on the owner across
  physical layers. An explicit map covers every compact block node, including
  inactive nodes whose tendency is zero. Missing/duplicate definitions, wrong
  owners, stale layers and incomplete transactions abort.
- `refresh_candidate_block_velocity_remainder` installs these owner results
  directly into its retained block storage. Once owner gradients are ready,
  the old geometry-owner native-tendency packing path is forbidden. Stage one
  continues using the previous path because its input lifetime is not migrated.

This does not create a full Domain-shaped solution snapshot. Retained gradient
results are block-owner active-node outputs. The compatibility arrays and
returns still needed by unmigrated consumers remain real memory/traffic costs.
Per-phase collectives and temporary owner-result buffers also remain; this is
not a performance-qualified implementation.

## Validation

All ten qualification checks passed. The source-bound result is
`parallel-blocks-stage234-local-results.json`, generated by
`test/parallel_block_profile/primitives_234/review_primitives.py`.
The review binds source, build commands, executables, inputs and logs. Earlier
prototype runs under `.stage234-validation/` are not qualification evidence.

- Checked 4-rank and optimized 41-rank trajectories each completed 12 steps,
  two remaps and restart coverage. Checkpoint fields, step states and all 62
  VTK payload members matched the same-rank Stage230 reference exactly.
- The long checked run compared 45,658,800 regular operations, 3,859,470 SW
  operations, 110,970 pentagon corrections and 20,364,930 final gradients
  bit for bit. These are operation counts, not independent repetitions.
- Rank40 in the 41-rank production run owned no Domains, but executed 532,080
  regular operations, 50,040 SW operations and 241,110 gradients. It also
  completed direct block retention after adaptation.
- The complete one-step dynamics oracle check and feature-off control passed.
- All six injected faults were rejected by their intended checks: regular,
  pentagon and gradient corruption; a missing resident operand; a stale
  thermodynamic layer; and an attempted old geometry-owner tendency capture.
The superseded `full-checked-4` run was deliberately interrupted when direct
retention was added; it must not be counted as a completed full test.

The validation gates were: independent intermediate comparisons; complete adaptive
and restart trajectories at 4 and 41 ranks; exact same-rank checkpoint, step
state and VTK comparisons; execution on a zero-Domain rank; a feature-off control;
and injected failures for regular, pentagon and gradient corruption, missing
resident operands, stale thermodynamic epochs and attempted old tendency capture.

## Remaining implementation order

1. Move the complete diffusion prepasses and their ordered edge/node exchanges,
   including same-rank copies across all levels. Supply their actual outputs
   directly to scalar and velocity physics. Preserve positive, unmasked diffusion
   divergence versus the negative, masked mass divergence.
2. Move mass flux restriction/divergence and the ordered velocity-source program
   together. Retain direct/restricted write ordering and required fine-level
   versions; do not replace geometry arrays with renamed full copies.
3. Remove compatibility primitive and source returns when their last readers
   have migrated; install scalar tendencies directly as well.
4. Supply stage-one/final-inverse, restart, post-physics and remap operand epochs,
   plus block-owned reference aliases. Require a complete cycle with former
   numerical inputs unavailable before deleting their old storage.
5. Remove the temporary RK return when RK consumes retained block state directly.
   Then return to measured optimization and block load balancing/splitting.

Main is unchanged. These changes are not committed by this stage.
